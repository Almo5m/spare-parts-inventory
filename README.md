# نظام إدارة مخزن قطع غيار السيارات

نظام بسيط بنستخدمه في المحل لإدارة المخزون والمبيعات والمشتريات وحسابات
العملاء. مش SaaS ولا حاجة تجارية، عملته لنفسي علشان أبقى مبسوط من
الدفاتر والإكسل اللي كنت بتوه فيها.

## الفكرة

كل حاجة بتدور حوالين: أصناف، مخازن (ممكن أكتر من مخزن)، عملاء وديونهم،
فواتير بيع، طلبيات شراء (بدل ما أتعامل مع "موردين" بالمعنى المعقد، كل
حاجة بتتشرى نقدًا وخلاص)، مرتجعات، جرد دوري، وتقارير تورّيني فين الفلوس
رايحة وجاية بالظبط.

أهم حاجة عندي إن الأرباح تبقى **دقيقة مش تقريبية** — يعني لما أبيع قطعة،
عايز أعرف بالظبط اشتريتها بكام (مش متوسط تقريبي)، فبنيت نظام دفعات
(Lots) بيتتبع كل عملية شراء لوحدها، والبيع بياخد من أقدم دفعة أول
(FIFO)، فالربح اللي بيظهرلي حقيقي 100%.

## التقنيات المستخدمة

- React + TypeScript + Vite
- Tailwind CSS (v4)
- Supabase (قاعدة بيانات Postgres + تسجيل الدخول + صلاحيات + Realtime + Edge Functions)
- Recharts للرسوم البيانية
- xlsx لتصدير التقارير لإكسل
- PWA — يتنزل كأنه تطبيق على الموبايل

## التشغيل محليًا

```bash
npm install
npm run dev
```

محتاج ملف `.env` فيه:
```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

(الملف ده مش مرفوع على الريبو عمدًا — كل واحد بيحط بياناته بتاعته).

## البناء والنشر

```bash
npm run build
```

بيتنشر تلقائي على Vercel أول ما أعمل push على الفرع الرئيسي.

## حاجات مهمة لازم أفتكرها لو رجعت للمشروع بعد فترة

- **كل المستخدمين المفعّلين ليهم نفس الصلاحيات بالظبط** — مفيش نظام
  أدوار حقيقي، ده قرار واعي مني لأننا فريق صغير وكلنا موثوق فينا. حتى
  إدارة المستخدمين (إضافة/تعديل username/تغيير باسورد حد تاني) متاحة
  لأي مستخدم مفعّل، مش بس لأصحاب المحل.
- **التعديل ممنوع في الفواتير والطلبيات — الإلغاء بس هو المتاح.** لو
  غلطت في فاتورة، بلغيها وأسجل واحدة صح.
- **الأسعار مش على مستوى الصنف** — كل طلبية شراء ليها سعر تكلفة وسعر
  بيع مقترح خاص بيها، عشان الأسعار بتتغيّر باستمرار في السوق.
- في مجلد `supabase/functions/` فيه Edge Function اسمها `manage-users`
  — لازم تكون منشورة (Deployed) على Supabase عشان "إضافة مستخدم جديد"
  و"تغيير اسم مستخدم" و"إعادة تعيين كلمة مرور" يشتغلوا من داخل الموقع.
  لو نشرتها مرة، مش محتاج أعمل حاجة تانية إلا لو غيّرت الكود بتاعها.

## حاجات لسه ناقصة أو محتاجة شغل مستقبلًا

- تحويل بضاعة بين المخازن (الجداول موجودة، الشاشة لسه لأ)
- ربط الأصناف بموديلات عربيات معينة
- Push notifications حقيقية حتى لو الموقع مقفول
- العمل من غير إنترنت مع مزامنة لاحقة
- Pagination للأصناف/العملاء لو الأعداد كبرت كتير
- مراجعة قرار "كل المستخدمين يقدروا يديروا بعض" لو الفريق كبر

## قاعدة البيانات (Supabase)

كل حاجة تخص الباك إند في مجلد `supabase/` وفيه ملف `README.md` بيشرح الترتيب. أهم نقطة: دوال الـ SQL
وسياسات RLS مش متسجلة في الريبو لسه، وخطوة سحبها من القاعدة شرحتها هناك (5 دقايق). لازم تتعمل مرة واحدة
عشان لو حصلت مشكلة نعرف نرجّع كل حاجة.

## ملف التوثيق الكامل

فيه ملف `توثيق-شامل.md` في جذر المشروع فيه كل تفاصيل قاعدة البيانات
والصفحات والقرارات اللي اتاخدت. لو محتاج حد (أو أي أداة ذكاء اصطناعي)
يفهم المشروع من الصفر، ابعتله الملف ده.
